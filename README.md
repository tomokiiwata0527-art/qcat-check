# Q-CAT 接着剤充填率チェック（v0.2.0）

外装タイル裏面の写真から**接着剤の充填率を算定し、合否判定と日別の帳票（午前・午後）を作る**Webアプリです。
画像処理はすべてスマホ／PCのブラウザ内で行います（写真を解析のために外部へ送りません）。

## できること

| 機能 | 内容 |
|---|---|
| 検査 | 写真撮影 → 四隅を指でタップ（拡大鏡つき・ドラッグ調整）→ 透視補正（98×264mm）→ 接着率を算定。1日に何件でも記録可（午前・午後の件数制限なし） |
| 自動判定 | 基準（初期60%）未満＝不合格／基準〜上限（初期65%）＝要確認／上限以上＝合格 |
| 最終判定 | 検査者が写真と解析結果を確認して「合格／不合格」を確定。自動判定と異なる場合・要確認の場合は備考に理由が必須 |
| 目視確認 | 補正画像と解析結果（青＝接着剤あり、赤＝なし）を並べて表示。感度スライダで調整 |
| 帳票 | A4横の「外装タイル 有機系接着剤 充填率検査記録（Q-CAT）」。ロゴ枠・会社名・署名欄（検査者/確認者/主任者）・総合判定つき。印刷／PDF保存、期間指定のExcel出力 |
| 記録の無効化 | 管理者が誤撮影などを「無効」にできる（削除はされず、帳票の集計から除外。理由を記録） |

## 動作モード

| モード | 条件 | 特徴 |
|---|---|---|
| 端末内保存 | `js/firebase-config.js` が空（初期状態） | そのまま動く。データはその端末のブラウザ内のみで**共有されない**。ブラウザのデータ消去で記録も消える |
| Firebase（共有） | `js/firebase-config.js` に設定を記入 | ログイン制。複数人で共有、撮影者と承認者を分離できる |

まず端末内保存モードで精度と使い勝手を試し、問題なければFirebaseを設定する進め方を推奨します。

## セットアップ

### A. GitHubで公開する（無料・約10分）

1. GitHubで新規リポジトリを作り、このフォルダの中身をすべてアップロード（`main`ブランチ）。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。
3. `Actions` タブで「Deploy to GitHub Pages」が成功すると、`https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける。
4. スマホで開き、ブラウザのメニューから「ホーム画面に追加」。

注意：GitHubの無料プランのPagesはリポジトリが**公開**になります。公開されるのはアプリのプログラムだけで、測定データは含まれません（Firebaseモードではログインとルールで保護）。非公開にしたい場合は、有料プランか、Firebase Hostingでの公開に切り替えてください。

### B. Firebaseで共有する

1. [Firebaseコンソール](https://console.firebase.google.com/) でプロジェクトを作成。
2. **Authentication** → 開始 → **メール／パスワード** を有効化。続けて設定の「ユーザーアクション」で**新規ユーザー登録（サインアップ）を無効化**し、**ユーザー**タブから使う人を手動で追加（登録されていない人が入れないようにする）。
3. **Firestore Database** → 作成（本番モード、ロケーション `asia-northeast1`＝東京）。「ルール」に `firestore.rules` の内容を貼って公開。
4. **Storage** → 開始（ロケーションは東京）。「ルール」に `storage.rules` の内容を貼って公開。
   - Storageの利用には従量課金プラン（Blaze）が必要な場合があります。条件は公式の最新情報を確認してください。この用途（1日2件）の使用量は小さい想定です。
5. **プロジェクトの設定 → マイアプリ → Web（</>）** を追加し、表示された設定値を `js/firebase-config.js` に貼る。コミットすると自動で再配備されます。
6. **管理者の登録**：Authenticationのユーザー一覧から、承認権限を与える人の **ユーザーUID** をコピー。Firestoreで `admins` コレクションを作り、**ドキュメントIDをそのUID**にして保存（中身は空でも、`role: "admin"` など何でも可）。
   - 管理者のみ「承認」「差戻し」ボタンが表示されます。一般ユーザーは撮影・閲覧のみ。

## 使い方（現場）

1. 「設定」で会社名・工事名・ロゴ・基準値を確認（初回のみ）。
2. 「測定」：施工日・時間帯・張り手・検査者・施工箇所・タイルを入力 → 写真を撮影 → 四隅を①左上→②右上→③右下→④左下の順にタップ（**短辺側から**）。
3. 「算定する」→ 赤い部分が実際の「接着剤なし」と合っているか写真と見比べる → **最終判定を確定** →「この結果を保存」。
4. 「日報」で施工日を選ぶと、A4横の検査記録が表示されます。「印刷／PDF」で出力（用紙：A4横）。

### 撮影のコツ
- 剥がしたタイル裏面を**真上から**、全体（四隅）が入るように。斜めだと面積がずれます。
- 影・直射日光・濡れを避ける。日陰で撮る。
- 背景（手・服）は多少写ってもよいが、四隅はタイルの角に正確に合わせる。

## 精度と限界（必ず読んでください）

- 算定は「色（黄み）で素地露出を分け、面積比を出す」方式です。サンプル写真4枚では、別実装（Python）の結果と0.2ポイント以内で一致しました。ただし**サンプルは同条件（曇天・日陰）の4枚だけ**です。接着剤の色が違う、強い逆光・濡れ・暗所の写真では精度が落ちる可能性があります。必ず赤の検出を目視確認してください。
- 60%付近の判定は、四隅のずれ（数ピクセル）で数ポイント動きます。そのため60〜65%は「要確認」とし、管理者の承認を必須にしています。
- **外周の除外幅（初期7%）は暫定値**です。Q-CATの要領書にある充填率の定義（測定範囲、縁の扱い、接着剤の付着とみなす条件）に合わせて設定画面で調整してください。
- 帳票の列・見出しは参考様式に合わせています。Q-CATの正式な記録様式がある場合は、そちらに合わせて調整が必要です。
- 充填率はブラウザ側で計算されるため、ログインしているユーザーが技術的に値を改ざんすることは理論上可能です。対策として、元写真・四隅座標・算定条件を全て保存し、第三者が再計算できるようにしています（記録の削除はルールで禁止）。
- 画像は長辺2000pxに縮小して保存・解析します。
- この結果を品質記録として認定機関・発注者が認めるかは、事前に監理者へ確認してください。本アプリは判定の補助であり、最終判断は人が行う前提です。

## 動作確認の状況

| 項目 | 状況 |
|---|---|
| 画像処理（JS）とPython実装の照合 | 4枚で一致（差0.01〜0.20pt）。`npm test` で再実行可 |
| 帳票レイアウト | 参考様式（A4横）に合わせて出力し、見比べて確認済み。件数が増えると複数ページ（見出し行は各ページに繰り返し） |
| 端末内保存モードの一連の操作（ブラウザ自動操作） | 確認済み：入力→四隅指定→算定→保存→承認→日報→Excel出力→再読込後の保持 |
| Firebaseモード（ログイン・共有・ルール） | **未検証**（開発環境からFirebaseに接続できないため）。設定後、最初に実機で以下を確認してください：ログイン／保存／別アカウントでの閲覧／一般ユーザーが承認できないこと |
| iPhone Safari・Android Chromeでの実機操作 | 未検証（デスクトップのChromiumで確認）。四隅タップの操作感を実機で確認してください |

## ファイル構成

```
index.html / style.css       画面
js/analysis.js               画像処理（透視補正・色分離・面積比・判定）
js/app.js                    画面の動作・帳票の生成
js/store.js                  保存層（端末内 / Firebase）
js/firebase-config.js        Firebase設定（ここに貼る）
firestore.rules              Firestoreのセキュリティルール
storage.rules                Storageのセキュリティルール
vendor/xlsx.full.min.js      Excel出力用ライブラリ（SheetJS 0.18.5、書き出しのみ使用）
test/                        検証スクリプト
.github/workflows/pages.yml  GitHub Pagesへの自動配備
```
